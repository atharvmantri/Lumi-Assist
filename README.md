# Lumi

Lumi is a local-first, always-on AI voice assistant for Windows. Say **“hey lumi”**, speak naturally, and Lumi can transcribe your request, call an LLM, use registered PC/web/productivity tools, and answer out loud.

The voice, speech-to-text model, tool execution, screenshots, conversation logs, and local state run on your machine. The configured LLM request is the main external API call.

## Install

### Supported platform

- Windows 10/11
- Python **3.11**
- Microphone + speakers/headphones
- 4 GB+ RAM
- NVIDIA GPU optional — CPU mode is supported

### Fresh install

Clone/download this repository, open PowerShell in the project folder, and run:

```powershell
.\install.bat
```

The installer creates an isolated `venv`, installs all required packages into that exact environment, downloads the Piper voice files, asks for an LLM provider/API key, writes local overrides, and runs diagnostics.

For a normal background/tray launch:

```powershell
.\launch.bat
```

For debugging, demos, or certification/review, use:

```powershell
.\launch_voice.bat
```

`launch_voice.bat` keeps the terminal visible, verifies the project virtual environment before startup, prints the exact Python/NumPy environment being used, and leaves useful diagnostics visible if startup fails.

> **Windows Python note:** do not repair Lumi with a bare `pip install ...`. That command may target a different Python installation. Use Lumi's interpreter explicitly:
>
> ```powershell
> .\venv\Scripts\python.exe -m pip install -r requirements.txt
> ```

## Reviewer / recertification path

A clean-machine validation should be:

```powershell
.\install.bat
.\launch_voice.bat
```

Then say **“hey lumi”**, wait for the chime, and speak a request.

Useful checks:

```powershell
.\venv\Scripts\python.exe -m core.diagnostics
.\venv\Scripts\python.exe tests\test_quick.py
```

The repository also runs a Windows + Python 3.11 GitHub Actions smoke test on pushes/PRs. It installs the same core requirements, verifies critical imports, compiles the Python code, and runs the regression suite.

## How it works

```text
Wake word
   ↓
Microphone capture
   ↓
faster-whisper speech-to-text
   ↓
LLM + tool calling
   ↓
Piper text-to-speech
   ↓
Speakers
```

The canonical runtime is `main.py`. Both `launch.bat` and `launch_voice.bat` use that same pipeline so the normal app and reviewer/debug path do not drift apart.

## CPU and GPU behavior

A fresh clone is intentionally safe on an ordinary Windows laptop:

- STT defaults to `small` + `cpu` + `int8`
- Piper runs on CPU
- CUDA packages are **not** mandatory core dependencies

During installation, if `nvidia-smi` is available and the optional CUDA runtime packages install successfully, the installer writes local STT overrides for GPU acceleration.

The optional NVIDIA packages are kept in `requirements-gpu.txt`; normal dependencies are in `requirements.txt`.

## Configuration

Repository defaults are in `config.yaml`.

Machine-specific settings generated by the installer are written to `config.local.yaml`, which is git-ignored and deep-merged on top of the repository defaults.

Secrets are stored in `.env`, which is also git-ignored.

Example local override:

```yaml
stt:
  model: "large-v3-turbo"
  device: "cuda"
  compute_type: "float16"

tts:
  speed: 1.1
```

## LLM providers

The installer supports OpenAI-compatible endpoints including:

- Hack Club AI
- OpenRouter
- OpenAI
- Google Gemini's OpenAI-compatible endpoint
- a custom OpenAI-compatible base URL

The selected API-key environment variable, model, and base URL are stored only in local configuration.

## Wake word

The default phrase is **“hey lumi”**.

If a trained `data/wakeword_models/hey_lumi.onnx` model is present and the optional livekit wake-word runtime is installed, Lumi can use it. A fresh install does **not** require custom wake-word training: the fallback listener energy-gates speech and verifies candidate phrases with a cached tiny Whisper model.

## Tools

Lumi auto-registers tools from `tools/*.py`. The catalog covers areas such as:

- applications and window control
- files and archives
- system/process/network information
- media, keyboard, mouse, and clipboard control
- screenshots and OCR
- web search/fetching
- timers, tasks, notes, memory, and conversation history
- developer/system automation

Browse [`docs/TOOLS.md`](docs/TOOLS.md) for the tool reference.

## Logs and local data

Runtime data is git-ignored. Conversation logs, learning state, screenshots, cached models, and generated files stay local unless a specific tool or LLM request explicitly sends data elsewhere.

Conversation entries are written under:

```text
data/conversations/YYYY-MM-DD.jsonl
```

Tool execution logs are written under `logs/`.

## Diagnostics

Run:

```powershell
.\venv\Scripts\python.exe -m core.diagnostics
```

The diagnostic command checks the actual runtime environment rather than a global Python installation. It validates:

- Python version
- config structure
- configured API key
- critical Python imports, including NumPy
- Piper model + config files
- Whisper cache/download state
- audio input/output devices
- screen capture
- Qt overlay initialization

A failed required check exits non-zero.

## Troubleshooting

### `ModuleNotFoundError: No module named 'numpy'`

Run:

```powershell
.\repair_env.bat
```

or:

```powershell
.\venv\Scripts\python.exe -m pip install -r requirements.txt
```

Do **not** rely on a global `pip install numpy`; it may install into another Python version while Lumi is launched with `venv\Scripts\python.exe`.

### CUDA / CTranslate2 error

Use CPU STT in `config.local.yaml`:

```yaml
stt:
  model: "small"
  device: "cpu"
  compute_type: "int8"
```

### Wake word appears dead

Use `launch_voice.bat` so wake-word listener errors remain visible. The fallback listener should work without a trained model and will download/cache its tiny Whisper verifier when first needed.

### Piper voice missing

Re-run `install.bat`. It downloads both:

```text
models/piper/en_GB-southern_english_female-low.onnx
models/piper/en_GB-southern_english_female-low.onnx.json
```

### Audio device issue

Run diagnostics and inspect the `audio devices` result.

## Development

Quick regression suite:

```powershell
.\venv\Scripts\python.exe tests\test_quick.py
```

Compile check:

```powershell
.\venv\Scripts\python.exe -m compileall -q core tools ui main.py lumi_app.py
```

To add a tool:

```python
from tools import tool

@tool(
    name="my_tool",
    description="What this tool does.",
    parameters={
        "type": "object",
        "properties": {
            "arg": {"type": "string"},
        },
        "required": ["arg"],
    },
)
def my_tool(arg: str) -> str:
    return f"Result: {arg}"
```

## Security

Lumi includes powerful local automation tools, including shell/Python execution. Run it only on a machine and account you trust. Keep `.env` private and review [`SECURITY.md`](SECURITY.md) before exposing Lumi to untrusted prompts or shared machines.
